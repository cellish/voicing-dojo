# Voicing Dojo — 設計とロードマップ

コードを判定ラインで弾く12キー対応のボイシング練習アプリ（旧称 Chord Master）。
このファイルは設計判断（理由つき）と長期フェーズを記録する。作業ログは [PROGRESS.md](../PROGRESS.md)。

## 1. 構成

- **単一ファイル `index.html`**（ビルド不要、iOS Safari / PC Chrome 対応）。配布と編集の手軽さを優先。GitHub Pages（main のルート）で公開。
- **テスト**: `node --test`。`test/harness.mjs` が本体スクリプトを vm 上でスタブ（DOM・Canvas・Tone.js）とともに動かし、時間を手で進めて通しプレイを確かめる。ブラウザを使わずに判定・進行・綴りを検証するため。
- **音源**: Tone.js v14.8.49（CDN）。ユーザー操作後に遅延初期化し、初期化は Promise 共有で1回だけ（多重タップでシンセが二重生成されるのを防ぐ）。
- **入力**: Web MIDI（ホットプラグ）、マルチタッチ画面鍵盤（`targetTouches` = 鍵盤上で始まったタッチのみ）、PCキーボード（A〜L）。
- **描画**: Canvas。`updateTimeline(dt)`（状態更新）と `drawFrame()`（描画）を分離し、一時停止中は描画のみ。フォント文字列はリサイズ・テーマ変更時だけ生成し、ブロック内の文字幅合わせもブロックごとに一度だけ計算。

## 2. タイミングと音

| 決定 | 理由 |
|---|---|
| Tone.js の `lookAhead` を 0 にし、ドラム・伴奏は描画ループから約60ms先の正確な拍時刻へ自前で予約 | 既定の0.1秒先行で演奏音・伴奏が描画より100ms遅れていた。フレーム単位で鳴らすと最大1フレームのぶれが出る |
| ベース・旋律は押鍵タイミングに関係なく常に拍ちょうどで鳴らす | 早押しで伴奏が前にずれるのを防ぐ |
| **コードの表示時間は秒で固定**（ゆっくり3.5 / ふつう2.8 / はやい2.2秒、コースとフリーで共通設定） | 画面の高さやBPMが変わっても「コードを読んで押さえる時間」を一定にするため。px速度の固定は低い画面で先が読めなくなるので不採用 |
| 低い画面で短いコードが続くときだけ表示時間を縮める（ブロック中心間隔 ≥ 高さ×1.15） | 表示時間が長いほどブロックは詰まるため |
| カウントインは表示時間以上を小節単位で確保（最低1小節） | 最初のコードが画面上端から降りてくるように |
| 判定幅 = ±1/3拍、ただし 180〜350ms に制限（上限 ±0.52拍） | 三連8分ぶんという音楽的な基準。和音は押し終わりで判定するので最低幅が必要、遅いテンポで緩くなりすぎないよう上限 |
| タイミング評価 Just（±70ms）に +20点。同じ和音を押さえ続けた場合（タイ）も Just | 和音の正しさ（100/50点）を優先順位の上に保つため、ボーナスは差分50点より十分小さくする |

## 3. 音楽データと判定

- **進行データ** `PROGRESSIONS`: 難易度別に `label/_int/_adv`、`deg/_int/_adv`、構成音（`notes`/`seventh`/`ninth`）、`bassMidi`、`melMidi`、任意で `beats`（既定4拍）。度数表記はこのデータから自動生成（手書きの度数文字列は不一致の原因だったため廃止）。
- **移調**: 五度圏順（C→F→B♭…、パッサカリアは原調の Gm→Cm→…）。原調の主音の文字は `SONG_META.baseTonicLetter`（既定 C）。ベース・旋律は**進行全体を同じオクターブだけずらして**音域に収める（1音ずつ折り返すとカノンの順次下行などが崩れたため）。
- **コード名の綴り**: 調の主音の文字から度数で綴る（G♭メジャーの IV は C♭）。±2以上の臨時記号になる場合のみ通常表記に戻す。A♭m は一般的な G♯m（♯5）に変更。キー名は ♭/♯ 記号、コード名は英字 b（テンション表記 b5/b9 と揃える）。
- **構成音名の綴り**: コード名のルートの文字に、ルートからの半音数に対応する度数の文字数を足して綴る（G♭メジャーの IV ＝ ド♭・ミ♭・ソ♭）。重変化記号も楽典どおり出す（G♯m の V ＝ D♯ の3度はファ♯♯）。データに綴りを持たせずに済むため。
- **オンコードの度数**は「V on 7」のように算用数字でベースの音階度数を書く（ローマ数字の V/VII は二次ドミナントと紛らわしい）。
- **判定**:
  - フル: 全構成音。5音以上のコードは完全5度を省略可（♭5は必須）。最低音がベースと一致で100点、不一致50点。
  - ガイドトーン: ルートからの音程で選ぶ。3度（無ければ sus4/sus2）＋7度（無ければ 6度→9度→5度）。ハーフディミニッシュの♭5はガイドトーンでは任意（シェルでは必須）。
  - ルートレス A/B: 必須音はルートレスと同じ。コードごとに A（3度が一番下）と B（7度、無ければ6度などが一番下）を交互に指定し、最低音が合えば100点、違えば50点。移動量は見ない。記録とキーごとのミスは A 始まりと B 始まりを分ける。
  - シェル: ベース音（ふつうはルート）＋ガイドトーン（3度・7度）。最低音がベースと一致で100点、不一致50点（フルと同じ）。3和音では7度が無いのでルート・3度・5度になる。
  - ルートレス: ルート以外。ガイド/ルートレスは前和音からの平均移動 ≤2.5半音で100点、最初のコード（比較対象なし）は100点。
  - 余分な音は1つまで許容し、その場合は表示で知らせる。MISS 時は不足音・余分な音を表示。
- **ミスしたらそのキーの1コード目からやり直し**（仕様どおり。転調が進行の途中で起きないようにする意味もある）。
- **スコア**: 1コード 100/50点＋Just 20点。ミスしたら、そのやり直し区間（コースは今のキー、フリー練習はセッション全体）で得た点を取り消し、さらに `MISS_PENALTY`（100点）を引く。コースの復習フェーズは加点しない。こうしないと、ミスして弾き直すほど点が増え、自己ベストが意味を持たないため。表示と記録は0点以上。
- **コンボ**: ミスなしで続けて弾けたコード数（50点の判定でも続く）。画面右下に表示し、10・25・50・100（以降100ごと）で大きく知らせる。
- **キーの色**: 一発合格＝金（★）、復習で合格＝銀（✓）、要復習＝橙（↻）。
- **ランク**（`RANK_RULES`）: S＝ミス0・Perfect率95%以上・ジャスト率70%以上、A＝ミス2以下・85%以上・40%以上、B＝ミス5以下・70%以上、ほかは C。Perfect率は100点の判定（Perfect / Smooth / Start）の割合。しきい値は実際に遊んで調整する。
- **著作権**: 旋律は、公有の作品から書き起こしたもの（パッサカリア＝ヘンデル、カノン＝パッヘルベル）か、作者自身のガイドトーン線のみ。保護期間中の作品の旋律は収めない。
- **枯葉サイクル → ヘンデルのパッサカリアに差し替え**: 枯葉は原曲（コスマ、1969年没）が保護期間中で旋律を鳴らせないため、同じ4度上行の循環（i - iv - ♭VII - ♭III - ♭VI - ii° - V - i）を持つ公有作品に替えた。仕様の枯葉型（iv 始まり）とは出発点が違う（i 始まり）。進捗は `RENAMED_STEP_KEYS` で新IDへ引き継ぐ。

## 4b. チャレンジ

コースと同じ「キーを順に弾き、ミスしたキーは最後に復習」の仕組みを使い、弾くキーの並び（`keyPlan`）と終わり方を変える。進行とボイシング（3和音 / ガイドトーン / 4和音 / ルートレス）はチャレンジ画面で選ぶ。
- **今日のドリル**: その日に最初に開いたときに、日付から課題（制覇済みのステップと次のステップの中から1つ）とキーを1つ決め、1日のあいだは変えない。1キー2周。クリアで「今日は済み」。
- **スピードアップ**: BPM 70 から、キーをクリアするたびに +5（上限 200）。12キーの後は最初へ戻って続ける。ミスしたら終了。記録は「キーをクリアできた最高 BPM」。プレイ中は BPM ボタンを効かせない。
- **耳コピチャレンジ**: フリー練習の耳コピ（コード名を隠し、出てくるときにヒントを鳴らす）で12キー。ヒントはコード和音かベース＋メロディ。
- **苦手キー克服**: キーごとのミス記録から、ミスがノーミスより多いキーを最大4つ選び、各2周。ノーミスで弾くと記録が減っていく。記録がなければ選べない。
- **連続練習日数**: 結果画面を開いた日を練習した日とする。昨日も練習していれば +1、空いたら1から。ホーム画面に表示。
- **実績**（`ACHIEVEMENTS`、20個）: コースの制覇、ランク S、コンボ、ジャスト率、スピードの BPM、各チャレンジのクリア、連続日数。結果画面で判定して知らせ、チャレンジ画面に一覧を出す。
- **演出**: 和音もタイミングも満点のとき左右に星、自己ベスト更新・ランク S・全ステップ制覇・実績解除のとき結果画面に紙吹雪（動きを減らす設定では出さない）。

## 5. UI・テーマ・保存

- **ホーム**: 「目標に挑戦する」（コース・チャレンジ）と「自由に練習する」（フリー練習）を枠で分ける。
- **バッジ**: 実績は画面では「バッジ」と呼び、自作の SVG（`badgeSvg`）で表示する。形は種類（コース=盾、腕前=六角、チャレンジ=丸、継続=花形）、金色は各種類の到達点、未獲得は色を抜いて破線。保存キーや内部の名前（achievements）は変えない。
- **プレイ画面の表示**: 音名は英字で、表記はコード名と同じ `#`・`b`（キー名は ♭・♯）。「音名 ON/OFF」でブロックの構成音を隠せる（ミスしたコードと耳コピの案内は出す）。KEY と、ルートレス A/B の「次の形」は、ゲーム画面のすぐ上の欄に出す。
- **コース一覧**: 上部にフェーズの目次（進み具合、押すと移動）。カードは最小幅180px（幅600px以下は150px）で並べ、画面幅は1200pxまで使う。カードのバッジはフェーズ内で共通の弾き方と違うものだけに出す。
- **テーマ**: モダン（既定の「自動」は OS のライト/ダークに追従。ライト・ダーク・ソフト系（ピンク・ラベンダー、丸ゴシックと角丸）の固定も選べる）とネオン（旧デザイン）。CSS 変数＋`html[data-theme]`（modern / retro）と `data-variant`（light / dark / soft / lavender）で切り替え、Canvas は `CANVAS_THEMES` の配色を使う。保存値は `modern`（自動）・`light`・`dark`・`soft`（ピンク）・`lavender`・`retro`。モダンでは絵文字アイコン（`.ico`）を隠す。
- **ゲーム画面**: ブロック内に度数バッジ（左）とコード名・構成音（右）。現在のキー（と A/B の次の形）はゲーム画面のすぐ上の欄、上中央に NEXT KEY、押下中の音は左下。
- **アクセシビリティ**: キーボード操作時のみフォーカス枠、オーバーレイ表示中は背後を `inert`、トグルの `aria-pressed`、転調・一時停止の読み上げ通知。
- **localStorage**: `chord_master_cleared_steps_v4`（進捗）、`chord_master_prefs_v1`（フリー設定・周回数・表示時間・オクターブ・ビート/メロディ・テーマ）、`chord_master_activity_v1`（練習した日：最終日・連続日数・最長・累計と、今日のドリルの課題）、`chord_master_keystats_v1`（進行×難易度×ボイシング×キーごとのミス・ノーミス回数）、`chord_master_achievements_v1`（解除した実績）、`chord_master_records_v1`（自己ベスト：スコア・ランク・ジャスト率・最大コンボをそれぞれの最高値で。コースはステップ×周回数、フリー練習は進行×キー×難易度×ボイシング×周回数×耳コピごと。スコアは弾くコード数で変わるため周回数も分ける。コース一覧には周回数によらない最高ランクを出す）。キー名は旧名称のまま維持（変えると既存の進捗・設定が消えるため）。

## 6. ロードマップ

- **Phase A（完了）**: 不具合修正、仕様との整合、音のタイミング改善、判定・採点の改良、テーマ、キー表示、表示時間の秒基準化。
- **Phase B（予定）**: 音源の見直し。あわせて Tone.js の CDN 依存を解消する（同梱するか、読み込み失敗時に案内を出す）。
  音を出す仕組みは道場シリーズの他アプリとある程度共通にする。その中で旋律に音価を持たせ（16分音符まで）、パッサカリアの旋律を原曲どおりに書き足す。
- **Phase C（完了）**: 構成音ヒント（ド・レ…）を調に沿って綴る。
- **Phase D（予定）**: 道場シリーズ共通の部品として、コード名・度数・構成音の整合チェックを作る（他アプリと共有。このアプリ単独では作らない）。
- **Phase E（完了）**: 楽しく続けられる工夫。自己ベストと NEW RECORD、コンボ、ランク（S/A/B/C）、キーの金・銀、チャレンジ（今日のドリル・スピードアップ・耳コピ・苦手キー克服、§4b）、連続練習日数、星と紙吹雪の演出、実績。
  - 残り: 実際に遊んでランクのしきい値・スピードの上がり方・実績の条件を調整する。
- **Phase F（完了）**: ドリルの追加。
  - 完了: キーの順番の選択、ブルース12小節・ドミナントの連鎖・裏コード・バックドア（フリー練習・チャレンジ・コースの応用フェーズ）、シェルボイシング（フリー練習・チャレンジ・コース Phase 3）。
  - 完了: ルートレスの A/B フォーム（F-2。コース Phase 5・フリー練習・チャレンジ）。仕様は下の「Phase F 残りの仕様」。案A（コードごとに一番上の音を指定）は採らない（2026-11-26 決定）。
- **検討中（2026-11-26）**: ルートレスの定番の V13（3・13・♭7・9。G13 の B 形は F・A・B・E）を使う ii-V-I を、新規の追加として検討する。今の `ii_V_I_maj`（上級の V は V9）は変えない。
- **Phase G（予定）**: 演奏の幅を広げる。
  - 右手と左手を分ける：左手（鍵盤の低い側）でボイシングを判定し、右手（高い側）は判定に含めず自由にメロディーを弾けるようにする。分け目の音の設定、MIDI 鍵盤の音域、画面鍵盤での扱いを決める必要がある。
  - 弾いた和音を伴奏として鳴らし続ける（ベース・ドラムと合奏する感じ）、クリア後に自分の演奏を聴き返す。
  - 短い曲を加える：保護期間が終わった曲か自作の曲で、旋律付き。旋律に音価を持たせる Phase B の仕組みが前提。候補は I Got Rhythm の A セクション（ガーシュウィン 1937年没、作曲は日本・米国・EU で公有。歌詞は保護期間中なので載せない）、Ja-Da（1918年）など。曲ごとに著作権の状態を確かめて README の権利表に書く。

#### F-2. ルートレスの A/B フォーム（完了）
- **形の定義**: ルートレス（`ninth` のルート抜き4音）のうち、**A フォーム＝3度が一番下、B フォーム＝7度が一番下**。7度の無い和音（6th 系）は6度を7度とみなす。3度・7度は `pickGuideTones` と同じ選び方（ルートからの音程）で決める。
- **どのコードをどちらの形で弾くか**: 進行の中のコードの番号（0始まり、周回によらない）で交互に決める。「A 始まり」なら偶数番目が A・奇数番目が B、「B 始まり」はその逆。4度上行が続く ii-V-I では、こうすると隣どうしの形が近くなる。
- **判定**: 必須の音はルートレスと同じ。そろっていて、押さえた最低音が指定の音（3度 or 7度）なら 100点「A Form!」「B Form!」、最低音が違えば 50点「形が違う（A/B）」。タイミングの Just 加点・コンボ・ミスの扱いは今までどおり。前の和音からの移動量（Smooth）は使わない。
- **表示**: ブロックの度数バッジの横に「A」「B」を出す。構成音のヒントは、指定の最低音から順に並べる（例：Dm9 の A フォームは「F・A・C・E」）。
- **データ**: `config.mode = 'rootless_ab'`、`config.formStart = 'A' | 'B'`。`buildChordTarget` に進行の中の番号を渡せるようにする（`spawnNextBlock` の `chordSeqIndex % 進行の長さ`）。
- **使う場所**:
  - コース：ルートレスのフェーズの最後に2ステップ。「メジャー ii-V-I（A/B フォーム・A 始まり）」と「（B 始まり）」。key は `p4-maj-ab`、`p4-maj-ba`。`diff: 'advanced'`。
  - フリー練習：ボイシングに「ルートレス A/B（A 始まり）」「ルートレス A/B（B 始まり）」を足す。3和音（初級）を選んだときは、ほかのルートレスと同じく注意を出す。
  - チャレンジのボイシングにも同じ2つを足す。
- **テスト**: メジャー ii-V-I・C で、A 始まりの必須音と指定の最低音（Dm9＝ファ、G9＝ファ、Cmaj9＝ミ、C6(9)＝ラ）、B 始まり（Dm9＝ド、G9＝シ、Cmaj9＝シ、C6(9)＝ミ）。最低音が違うと50点になること。コースの2ステップを通しプレイできること（ハーネスの `playLoop` は最低音を指定の音にして押さえるよう直す必要がある）。
